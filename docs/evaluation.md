# 批量检索与人工评审

0.2.0提供`nyr eval run`：用同一份题集测试不同模型/参数，把真实返回证据保存下来供人工判断。
当前不自动判断业务正确性，不自动生成标准答案；证据集整理与Recall@K等离线评分为Spec0066后续B/C片，尚无对应命令。

## 1. 安装及启动

```sh
python -m pip install --upgrade naiyue-rag==0.2.0
nyr --version
nyr --config /absolute/path/config.yaml
```

先退出旧版nyr再启动新版；客户端会拒绝配置/执行合同不同的旧服务，不自动杀占用进程。
复用已配置模型和已摄取知识库；模型、维度与表示不变时，无需为本次Python包升级重新编码。
更换Embedding模型时必须为该模型建库；推荐独立storage_root，材料和切分等对照条件固定。
每个服务实例只使用其配置的一组模型；同时开多个实例时使用不同端口。

## 2. 准备题集

保存UTF-8文本`questions.jsonl`，每行一个JSON对象；每题只需`id`和`query`。
id用字母/数字/下划线/短横线，1–64字符，整份文件不能重复；query为你自己的非空问题。

| 字段 | 必填 | 内容 |
|---|---|---|
| id | 是 | 固定题目编号，跨模型保持相同 |
| query | 是 | 实际问题；JSON字符串中换行写为反斜线n |
| reference_notes | 否 | 已知依据或待核对位置，字符串 |
| checkpoints | 否 | 必须关注的条件/步骤，字符串数组 |
| scope_document_ids | 否 | 限定文档ID数组，ID取自nyr documents |
| exclude_document_ids | 否 | 排除文档ID数组 |

reference_notes/checkpoints只进入人工报告，不发送给Embedding或重排模型。
没有参考依据时省略字段即可，不要求先标注答案。不提供默认题目或自动生成的业务标签。
空白行允许，重复JSON键/未知字段/NaN/无效ID/重复题号明确拒绝。

## 3. 运行

在另一个终端使用与常驻服务相同的配置：

```sh
nyr eval run --config /absolute/path/config.yaml --questions /absolute/path/questions.jsonl --output /absolute/path/runs/model-a
```

输出目录必须是新目录，不能位于知识库或索引根下；不自动覆盖旧运行和人工评审。
Linux/macOS新建结果目录权限0700、文件0600；Windows沿系统ACL。报告包含问题及返回原文，请按公司材料规则保存。
默认最多1000题、题集最多16777216字节，可通过--max-questions/--max-input-bytes指定正整数上限；每题请求仍受配置的HTTP预算限制。
未发现常驻服务时沿普通nyr命令的规则创建临时实例，结束仅清理本次拥有的实例。
不隐式摄取/换模型/重试，不更改真实配置。

开始时固定活动版本，所有题传同一expected_revision；资料或服务身份变化停止本批。
单题模型超时/模型错误记录后继续；服务失联/认证失败/输出IO错误结束本批。
Ctrl+C保留已记录的结果，停止后续题；后台收尾状态可用nyr status查看，取消不表示底层立即退出。

## 4. 看结果

| 文件 | 用途 |
|---|---|
| run.json | 包版本、模型/参数白名单、资料清单和活动版本、题集摘要、执行状态/未执行题 |
| results.jsonl | 每题完整返回JSON或安全错误码；后续离线评分使用 |
| report.md | 逐题问题、人工提示、原文证据、来源位置、各路排名/分数、预算排除、耗时/错误 |
| review.csv | id/request_sha256/人工judgment/notes，后两列初始为空 |

人工judgment可填“足够”“部分”“无帮助”“不确定”，备注写关键缺失项或版本疑问。
该表不自动变成标准证据集；候选排名和模型分数不是业务正确性的依据。
JSON保留原文；Markdown将材料内容转义展示，CSV防止公式执行；终端只输出运行汇总。
凭据、完整模型注册表、向量及原始模型响应不进入产物。

run状态completed表示全部查询执行成功（空证据也属于有效执行）；partial表示有单题请求失败但跑完；aborted表示中途结束。
退出码0为完整无请求错误，2为输入/执行/输出失败，130为Ctrl+C；不是质量分数。
进程被强杀/磁盘故障可留下running状态或未完成文件，应保留并视为不完整；不要当作完整批次评分。
没有覆盖/恢复旧目录的选项，重跑请指定新输出目录。

## 5. 公平对照和后续评分

两模型使用相同题目ID/实际问题/范围、相同来源文件内容；固定切分、检索/证据预算等不打算研究的变量。
先关闭重排比较Embedding，再固定Embedding比较重排，有助于判断变化来源。顺序跑题不是并发吞吐基准，首题可能含冷加载。
模型版本/digest应明确固定；同名权重被替换不能仅靠模型名判断相同。

本版保存stage=final_evidence，只能评价最终交付证据；排名深度为min(fusion_top_k,rerank.top_k)。
JSON证据rank保留重排前装配位置，预算排除后可能不连续；人工报告按最终返回次序编号。
以后自动评分会使用实际保存阶段和K，不从最终Top5推算上游Recall@20。
人工核对参考证据时保留来源版本、原文和必要条件，可接受不同但等价的出处；未标注不等于无关。
当前源码、测试和本机安装证明功能可执行，公司Linux真实材料/模型质量需要你实际运行后判断。
