# ADR 0001：第一轮检索路线对照范围

日期：2026-10-09。状态：用户已确认实验候选范围；不是最终技术栈决定。

## 问题与决定

新需求需要结合多份历史需求、模块背景和旧用例。用户确认优先并列验证：

- A：片段检索＋已有Markdown引用/需求用例名称关系。
- B：LightRAG图＋片段检索。

依据为[Mock Q01路径比较](../research/mock-q01-route-comparison.md)、用户描述的真实文档结构和现有[定向调研](../../research/naiyue-rag-knowledge-base/report.md)。用户回复“好的”确认上轮提出的A/B优先范围；不登记为技术理解或预期证据标注通过。

## 取舍与后果

A考察已有导航与内容检索是否足够、每种机制增加什么收益与噪声；B考察模型抽取关系是否补充关联证据，同时测来源保持和额外调用代价。优先A/B控制第一轮规模，Microsoft GraphRAG和RAGFlow保留相关候选角色。

内部对照建议：A逐步加向量/融合/已有关系，B比较naive与mix。切分组件、接口、模型、存储、预算、评价阈值仍须在实验Spec中明确。上述路线确认本身不授权安装、真实服务调用、发布、push或完整产品实现；其他已确认实验的授权和结果见各自Spec。

若定位/更新契约无法满足、真实材料效果退化、额外调用超预算，或任务转为全库概括等，应重新评价路线。Mock结果只作机制证据；最终选择须结合远端真实材料。

## 2026-10-09：共同证据要求已确认

用户回复“接受”，确认以下返回证据原则：

- L0/L1/L2普通正文按小标题下的完整说明组织；过长时沿段落拆分，附文档标题、章节路径与实际原文位置。公式及解释其计算顺序的说明应保留在可共同阅读的证据中。
- 测试用例以完整一条为基本单位，保留前置条件、步骤、预期及其他原有字段，并附表格列名、测试维度、来源/覆盖说明；附加上下文与用例正文分别标注出处，不冒充连续原文。
- 引用依赖保留在原片段中；需要补充时，作为另一条有独立出处的证据返回，不自动继承被引用用例的全部步骤和预期。

这是返回证据的业务要求，不指定各路线内部索引必须使用相同结构，也不确认具体解析组件、切分上限、超限行为、依赖扩展算法或新实现。若最终索引片段不同，实验需报告差异，不将整体结果差异全部归因于图。

助手只读统计：排除模拟本次任务文件后，11份候选源文档共9080个Unicode字符（含Markdown语法；当前L1仍是导航而非历史时点快照）。没有新增服务请求或代码改动；用户确认不登记为理解/独立实现通过。
