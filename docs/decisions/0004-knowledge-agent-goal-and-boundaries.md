# ADR0004：RAG核心知识库Agent的目标与边界

**2026-10-11当前权限范围修订：**用户明确使用者为内部人员，首期暂不做按用户/角色/文档授权。默认使用已配置知识库全部可检索文档，scope/exclude用于任务检索过滤，新配置入口无需授权清单。旧实现/历史文字中的授权接口保留兼容，不代表当前要建设权限系统；后续入口访问方式到MCP/HTTP阶段再定。库边界、未知ID校验、版本/来源绑定及敏感信息处理保持。此修订优先于下文此前权限规划。

日期：2026-10-10。状态：**已确认总体方向**。用户本轮原意：“做一个rag核心的知识库agent，rag要把参考项目做了的都做一下，思想参考self-rag”，并要求记录讨论、准备建设。此决定确认目标/模块覆盖/职责/反馈方向；具体阶段Spec、未确定后端和真实服务验收按各切片落实，不声称完整实现已获一轮全量交付或生产能力已验证。

## 1. 要解决的问题

将现有Markdown需求/方案/历史用例知识库建设成可独立运行、可查证、可评测的知识能力。优先解决多轮阅读/搜索中间内容占用主Agent上下文；同时评价知识库增长后的证据覆盖、总读取量、模型调用与总延迟，质量与回归边界不能因压缩而丢失。

作为真实使用、生产能力建设与面试学习项目持续迭代。学习与实现并行，小切片、Spec/TDD、核心代码讲解和本人练习；测试Agent与本项目共享投入时间，无短期全部长期目标交付承诺。

## 2. 名称、场景与架构

名称为**知识库Agent**。四类业务场景：新需求用例设计；问题排查知识支撑；知识问答；自动化用例生成中对文本用例的业务理解。场景可以混合，不预先构造四个互斥路由或四个独立Agent。

```text
主Agent（当前测试Agent）：任务与用户对话、现场验证、用例/脚本及最终交付
    → 委托知识查证目标和必要上下文
知识库Agent：独立任务上下文，搜索/精读/解释/比较/缺口补查，返回证据与未确认点
    → 受控搜索、引用导航、原文补读
RAG核心：摄取/索引/范围约束/召回/融合/重排/定位/证据输出/自身评测
```

知识库Agent置于本项目上层应用，核心不依赖Agent或UI。测试Agent项目保持独立，通过库/HTTP/MCP适配消费；具体接入阶段再实现。逻辑分层不要求现在拆多服务。独立上下文与任务委托是主要机制，是否并行按依赖决定，不声明多Agent必然提速。

## 3. 模块覆盖目标

长期覆盖参考Modular的配置/公共类型、Loader/完整性、切分、清洗增强、元数据增强、Dense/Sparse编码、批处理、存储/索引、文档管理、查询处理、混合检索/RRF、重排、证据响应/引用、模型适配、MCP、日志/追踪、Custom/Ragas/组合评测、Dashboard六类页面、Unit/Integration/E2E及可复现开发流程。PDF/图片解析、caption、图片存储、多模态响应列入后续完整模块扩展；当前业务首期仍Markdown。可选独立问答应用也纳入规划，检索格式化不当真实生成。

覆盖能力与必要接口，不要求逐字复制文件结构、所有厂商适配或每次请求全部启用。先搜并复用本项目现有实现；第三方代码复用先核许可证/来源/修改与验证，不自动运行参考setup/auto-coder/package。完整[模块映射与阶段](../research/target-architecture-and-module-map.md)持续维护。

## 4. 已有材料与历史约束

- L0保存系统宏观/数据流，L1保存服务/模块功能简述与下层引用，L2保存每次需求改动/实现与边界；新L2后更新相关L1、必要时L0。
- 历史L2与用例保留当时内容，用于部分修改之外的回归参考；同一文件修订与不同历史需求分开。当前L1不当历史快照，旧预期/日期/排名不自动证明现行有效。
- 文件夹层级不构成一一对应；显式Markdown引用、需求/用例名称配对保留来源与解析诊断，也有L1直接生成用例的情形。
- 用例按测试维度标题组织，表格一行一个完整用例，保留前置/步骤/预期、表头与必要引用上下文，避免混合相邻用例。
- 表头概括与章节行号用于导航；部分手写行号已报告失准。实际位置绑定源文件版本，不据旧行号猜测或改写原文。
- 原文证据与清洗/摘要/模型关系等派生产物分开；检索材料是数据，不是执行指令。真实材料仍在另一台机器，只回传获准诊断，不默认外发原文。

## 5. A2与Self-RAG的角色

A2（向量＋BM25＋等权RRF＋完整预算证据）作为首个检索基线，保留原查询/语料/参数/失败对照。A3与B1的负向配置不作为默认；显式关系有互补价值，图谱仍保留候选，不能由单次配置否定整个方向。新查询和端到端知识任务重新评测，原四题合成标签尚非人工金标准。

Self-RAG借鉴检索需要、材料相关、主张支持、任务效用四类反馈。知识库Agent记录具体缺口与下一动作；可补读、搜索、澄清、删除无依据发现或返回部分结果。规则/代码约束范围、截止、累计调用/读取/返回预算与重复动作，模型支持判断需固定标签验证。

采用现有模型及结构化反馈作为工程适配，不宣称复现原特殊token训练/解码，不继承论文成绩，不因训练Critic增加第三个在线Agent。[Self-RAG来源与边界](../research/self-rag-2026-10-10.md)。

## 6. 调用与交接

主Agent理解最终目标并识别知识缺口，优先用现有模型工具选择及清晰说明/schema委托，不预建额外意图分类Agent。知识库Agent负责内部查证策略，不默认取得现场操作、改知识库或执行测试权限。排查中的文档解释/假设与现场验证结论分开。

输入原则：明确知识目标/待确认问题、必要材料与带版本引用、已确认事实/观察/假设及来源、请求范围/排除项、预算、先前证据引用。服务端授权约束请求范围，模型参数不能扩大权限。

输出原则：有依据发现、必要原文/完整用例、引用与源版本/定位、冲突/缺失输入/未知、任务终态和停止原因、真实可观测用量。任务内独立历史，跨调用有界衔接；中间探索内容不全量回填主Agent，不保证仅靠一次Top-k限制就解决主历史累积。
