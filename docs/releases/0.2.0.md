# Naiyue RAG 0.2.0

本版把`nyr`接入常驻共享检索服务，并增加`nyr eval run`，用于逐个测试模型/参数、保存真实检索结果并人工评审。

## 主要变化

- 同一服务复用已校验版本资源，连续查询不再反复完整解析整个资料包与重建索引客户端。
- 默认2条查询执行、20条等待，期限可配置；超时/连接断开请求协作取消，后台真正退出后归还槽位，不自动重试。
- 查询与摄取/移除分别执行；更新完成后新请求使用新版本，正在运行的查询保持原版本。
- `nyr`默认启动共享服务；增加`status`、`document`、`remove`，`query`增加文档范围/排除参数。
- 增加`nyr eval run --questions questions.jsonl --output runs/model-a`，保存run.json、results.jsonl、report.md与空白review.csv。
- 跑题固定资料版本；人工提示不发送给模型；单题模型失败保留后继续，版本/服务身份变化停止；输出目录不能位于知识库/索引根下，POSIX产物权限限当前用户。
- 修复源目录离线时移除文档失败、并行更新阻塞服务线程池，以及客户端早于服务端期限超时的问题。

## 升级与使用

先退出旧版nyr，在原Python3.12环境升级：

```sh
python -m pip install --upgrade naiyue-rag==0.2.0
nyr --version
nyr --config /absolute/path/config.yaml
```

另一个终端运行：

```sh
nyr status --config /absolute/path/config.yaml
nyr eval run --config /absolute/path/config.yaml --questions /absolute/path/questions.jsonl --output /absolute/path/runs/model-a
```

题集每行一个JSON对象，必填id与query，不要求已有标准答案。格式、报告和失败处理见[评审说明](../evaluation.md)。
原配置无需新增retrieval节即可使用默认调度参数；升级不会改写用户配置、知识库或旧结果。
模型/维度/表示保持时不因包升级重新编码；更换Embedding必须重建对应索引，推荐使用独立storage_root。

## 模型附件

本版沿用0.1.0的Qwen3-Embedding-0.6B Q8_0权重、Apache-2.0许可证和来源清单，同标签Release提供三份附件。
GGUF SHA256为`06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439`，639150592字节。
已载入该模型的开发机可继续使用既有模型名和digest；不必为Python包升级重复导入。
Python包不包含模型权重或Ollama程序，安装说明见[本地Embedding](../local-embedding.md)。

## 当前边界

服务仍为认证回环入口，MCP、Git定时同步、回答生成尚未提供。
本版评测保存最终返回证据，人工证据集整理和Recall@K等自动评分属于Spec0066后续B/C片，尚无对应命令。
并发数不是CPU推理吞吐保证；公司Linux真实资料/真实模型质量由用户验收。底层调用永久阻塞时第一版仍需人工重启。
