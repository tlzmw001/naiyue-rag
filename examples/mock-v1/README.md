# Mock Markdown 知识库 v1

全部正文是助手构造的合成材料。照片提供结构参照，未转写真实业务、凭证、内部地址或真实路径；被裁切的内容没有被补写成“原文”。名称、公式、数值、日期和规则均为合成。

## 可以做什么

- 用 L0/L1/L2 及旧用例解释跨文档检索路径。
- 后续核验标题、块引用、表格、代码、长行、单元格 `<br>` 和转义竖线保留。
- 检查需求与用例配对、缺少配套用例、L1来源用例、原始值与最终值区分。
- 作为选型实验的机制探针，不证明真实材料上的召回、图谱收益或生产能力。

## 目录与任务

仅 `knowledge/` 是候选摄取范围。README、manifest.json、tasks.json 不能进入知识索引，否则会泄漏预期证据。

- L0：1份系统说明。
- L1：3份模块导航，按模块放子目录。
- L2：8份文档，含历史需求、用例、模拟本次任务和干扰材料。
- `L2_REQ_004_combined_strategy.md` 是模拟本次需求；没有对应新用例。
- `tasks.json` 是助手构造的任务及候选证据，不是用户人工金标准；只供讨论或后续独立评测器消费。
- `manifest.json` 记录样本身份、角色与结构探针，属于样本资产描述，不是运行服务配置。

## 复现的结构与补造的内容

照片可见结构：分层目录、Markdown相对引用、表头摘要和章节索引；维度标题下有来源/覆盖说明；九列表格一行一个用例，单元格含 `<br>`、行内代码和公式，部分用例复用前面用例条件。

合成补造：所有文件正文、字段及模块名称、需求时间线、公式、异常标记和期望数值。这里的简单规则故意便于手算；措辞与关系可能比真实材料更规整。

## 特殊样本

1. 初始需求表头故意写 `L999-L1005`，目标章节实际在文件内其他行；不能以手写位置作为原文定位。
2. 初始用例有超过500字符的物理长行，步骤/预期不能按屏幕折行理解。
3. TC-02引用TC-01的部分条件；不同文档内TC-01重复出现，ID需按文档范围解释。
4. 字段命名需求没有与本次需求直接互链，没有配套用例；是否有用取决于查询内容。
5. 当前L1导航已包含本次任务，不能当作历史时点快照。
6. 存储轮换文档有“策略/合并/覆盖”等重叠词，语义与目标不同。
7. 旧用例保留旧校准预期；本次需求只修改其中部分，不自动淘汰全部历史用例。
